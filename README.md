# Linux-IM-Server

Linux C++ 即时通信服务器学习项目。先完成 TCP 通信与 epoll Reactor，再逐步加入线程池、MySQL、Redis 和 HTTP/WebSocket。

## 当前进度

当前处于第 2 周：epoll 多客户端、临时用户名、群聊与私聊。

- CMake 生成 `IMServer`、`IMClient` 两个可执行程序。
- 使用 C++17，关闭编译器语言扩展，开启 `-Wall -Wextra -Wpedantic`。
- 服务端校验参数数量及端口范围；客户端额外校验 IPv4 地址。
- 使用 RAII `Socket` 管理文件描述符，禁止拷贝，析构时关闭有效 fd。
- `Tcpserver` 使用单线程 epoll LT 模式，监听和连接 socket 均为非阻塞，可同时管理多个客户端。
- 使用 `std::unordered_map<int, clientstate>` 保存连接、接收缓冲、发送缓冲及发送偏移量。
- 服务端按换行符提取完整消息，广播给发送者以外的所有在线客户端。
- 支持 `/name` 设置连接期间的唯一用户名，通过用户名索引查找在线连接。
- 支持 `/msg` 私聊，正文只发给目标用户，发送者收到入队结果提示。
- 使用统一的消息入队和连接清理方法，断开时同步移除用户名索引。
- 发送队列处理部分发送和 `EAGAIN`，有待发送数据时订阅 `EPOLLOUT`，发送完后取消订阅。
- `Tcpclient` 使用 poll 同时关注标准输入和服务器消息，支持输入缓冲、空行、连续多行和 `/quit`。
- 收发处理 `EINTR`，发送使用 `MSG_NOSIGNAL`；连接关闭时通过 RAII 回收资源。
- 已接入 CTest 和 Python 简单通信测试。

客户端退出只清理该连接，服务端继续服务其他连接并接收新连接。用户名仅在连接期间有效，尚无注册登录或身份认证；任何新连接都可以申请当前未占用的名字。消息持久化、数据库和 HTTP/WebSocket 尚未实现。

## 环境要求

- Linux
- 支持 C++17 的编译器（如 GCC）
- CMake 3.16 或更高版本
- Make 或其他 CMake 支持的构建工具
- Python3（启用默认的 CTest 简单测试时需要）
- Git；后续调试使用 GDB

当前阶段不依赖 MySQL、Redis、OpenSSL 或 Boost，后续按模块引入。

## 构建

以下命令均在项目根目录执行。

Debug 版本，用于开发和 GDB 调试：

```bash
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug -j
```

Release 版本，用于后续性能测试：

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release -j
```

只构建程序、不配置测试时，可在配置命令后追加 `-DBUILD_TESTING=OFF`。

## 运行

在终端一启动服务端：

```bash
./build/debug/IMServer 8888
```

服务端绑定所有本机 IPv4 接口，通过 epoll 等待事件。在终端二、三、四分别启动客户端：

```bash
./build/debug/IMClient 127.0.0.1 8888
```

服务端接受一个端口参数；客户端接受一个 IPv4 地址和一个端口参数。端口必须是完整的十进制数字字符串，取值范围为 `1–65535`。客户端暂不接受域名或 IPv6 地址。

运行 Release 版本时，将路径中的 `debug` 替换为 `release`。

### 命名与群聊

连接后，先在三个客户端分别设置用户名：

```text
/name Alice
```

```text
/name Bob
```

```text
/name Carol
```

每个客户端只输入自己的命名命令。用户名为 1–32 字节，只允许 ASCII 字母、数字和下划线，区分大小写；在线用户名不能重复，每个连接只能成功命名一次。命名失败可以重试，命名成功返回确认提示。

未命名时发送聊天内容或私聊命令，服务端返回“请先设置用户名”。命名后，普通文本作为群聊发送。例如 Alice 输入 `hello world`，Bob 和 Carol 显示：

```text
[Alice]:hello world
```

发送者不收到自己的广播。客户端即使没有键盘输入，也会显示其他客户端的消息。当前实现将群聊广播给发送者以外的全部连接，包括尚未设置用户名的连接；临时命名不构成访问控制。

### 私聊与命令

Alice 输入：

```text
/msg Bob hello there
```

只有 Bob 收到正文：

```text
[private Alice]:hello there
```

Alice 收到“私聊消息已入队”，Carol 不收到该私聊。正文中的空格会保留。入队成功表示服务端已将消息加入目标连接的发送队列，不保证对方已收到或阅读。

| 输入 | 行为 |
| --- | --- |
| `/name Alice` | 设置当前连接的用户名 |
| 普通文本或空行 | 命名后发送群聊 |
| `/msg Bob 消息` | 命名后向 Bob 发送私聊 |
| `/quit` | 客户端本地退出，不发送该命令 |
| 其他以 `/` 开头的文本 | 返回未知命令提示 |

重复命名、用户名已占用、非法用户名、私聊目标离线、给自己私聊或私聊参数缺失时，服务端返回错误提示。私聊目标和正文不能为空；当前单独输入 `/msg` 返回未知命令提示。

### 退出与清理

- 输入 `/quit`：客户端正常退出，该命令不会发送给服务端。
- 标准输入 EOF：客户端将剩余的非空输入补上换行并发送，然后正常退出；终端中可在空输入行按 Ctrl+D。
- 服务端收到连接 EOF：清理该连接，继续处理其他客户端。
- 正常断开或连接错误导致清理时，删除该连接的用户名索引；其他连接随后可以重新使用这个名字。
- 在服务端终端按 Ctrl+C：结束服务端；客户端可通过 socket 接收 EOF 检测关闭。当前尚未实现信号驱动的优雅退出。

### 临时消息协议与限制

TCP 不保留消息边界。当前以 `\n` 为分隔符：服务端缓存不完整行，一次接收包含多行时逐行处理，只有完整行才进入命令或聊天处理。直接使用其他 TCP 客户端时，关闭前未补换行的尾部数据不会处理。

- 每行正文最多 64 KiB，不包含末尾换行，按字节而不是字符计数；超限断开该连接。
- 每连接未发送数据最多 1 MiB；入队超限或更新 epoll 关注失败时，由调用方清理对应连接。私聊目标入队失败时清理目标并尝试通知发送者。
- 客户端目前仍使用阻塞式连接和发送，等待连接或大数据发送期间可能暂时无法处理其他事件。
- 消息只转发给当前在线连接，不保存、不重放，也不提供接收或已读确认。

后续再升级为包含类型和长度的自定义帧协议。

## 自动测试

构建完成后运行：

```bash
ctest --test-dir build/debug --output-on-failure
ctest --test-dir build/release --output-on-failure
```

当前 `SimpleTCPTest` 仅验证客户端发送 `hello` 后正常退出，并在服务端输出中找到输入内容。脚本尚未先设置用户名，因此即使通过，也不能证明消息已获准聊天或已被转发；用户名、群聊和私聊需按下面的手动场景验证。后续应将命名和回复检查补入脚本。

测试固定使用端口 `8888`，运行前确保端口空闲，两种构建的测试依次执行。服务端测试输出保存在对应构建目录的 `server.log`。

测试设有客户端等待和 CTest 总超时，脚本在 `finally` 中终止并回收测试启动的服务端进程。

## 手动验收

Debug 和 Release 两种构建都应无警告通过编译，并分别检查以下场景。

### 参数与连接

| 场景 | 预期行为 |
| --- | --- |
| 先启动服务端，再连接 `127.0.0.1:8888` | 客户端连接成功，服务端继续接受其他连接 |
| 缺少参数或多余参数 | 打印用法，返回 1 |
| 端口 `0`、`65536`、`-1`、`8888abc`、空字符串、超大整数 | 拒绝，返回 1 |
| 客户端地址 `999.1.1.1`、`abc`、空字符串 | 拒绝，返回 1 |
| 两个服务端绑定同一端口 | 第二个绑定失败，返回 1 |
| 本机目标端口没有监听服务 | 客户端连接失败，返回 1 |

端口 `1`、`65535` 均能通过参数校验，但后续绑定或连接能否成功取决于权限、端口占用和目标服务状态，不能仅据合法参数断言程序最终返回 0。

例如，执行错误参数测试后立即查看退出码：

```bash
./build/debug/IMServer 8888abc
echo $?
```

### 收发与断开

先为三个客户端分别设置 Alice、Bob、Carol，再进行群聊和私聊测试。

| 场景 | 预期行为 |
| --- | --- |
| 未命名发送普通消息或私聊 | 提示先设置用户名，不转发输入内容 |
| 空用户名、非法字符、33 字节用户名 | 拒绝，仍可重新命名 |
| 1/32 字节用户名、大小写不同的名字 | 合法且未占用时接受 |
| 重复使用在线用户名、已命名后再次命名 | 拒绝 |
| 三个客户端连接，其中一个不输入 | 其他客户端仍能发送，空闲客户端也能接收广播 |
| 连续输入多行、带空格文本及空行 | 其他客户端完整收到，发送者不收到自己的广播 |
| Alice 私聊 Bob，正文含连续空格 | 仅 Bob 收到完整正文，Alice 收到入队提示，Carol 无私聊内容 |
| 目标离线、自发私聊、正文为空或未知命令 | 返回错误提示，不泄漏正文给其他连接 |
| Bob 退出后新连接使用 Bob | 命名成功，新私聊发给新连接 |
| 发送超过 4096 字节的一行，例如 20000 字节 | 分批接收后形成完整消息，无截断 |
| 一行分多次发送、一次发送多行 | 不完整行先缓存，完整行逐条广播 |
| 正文恰好 64 KiB / 超过 64 KiB | 边界值接受，超限连接断开 |
| 输入 `/quit`，或标准输入到达 EOF | 客户端返回 0，服务端继续运行 |
| 强制结束客户端进程，再连接新客户端 | 旧连接清理，新连接可正常聊天 |
| 服务端关闭，客户端标准输入仍打开 | 客户端能检测到服务器断开并退出 |
| 对端重置连接后继续发送 | 客户端检测到发送错误后返回 1，不被 SIGPIPE 终止 |
| 所有消息发送完毕，客户端保持空闲 | 不持续触发无用的 EPOLLOUT，不出现忙循环 |

对端关闭后，发送不保证立即报错。客户端同时通过 poll 的接收事件检测 EOF 或错误；大数据阻塞发送期间仍可能延迟感知。

也可以在服务端启动后，通过管道验证连续发送与标准输入 EOF：

```bash
printf '/name PipeUser\nhello\nhello world\n\n' | ./build/debug/IMClient 127.0.0.1 8888
```

确保 PipeUser 未被占用。管道发送者在输入结束后退出，未必来得及显示服务端命名回复；在另一个已连接且保持运行的客户端观察 `[PipeUser]:` 广播。服务端不需要在每个客户端退出后重启。

服务端已设置 `SO_REUSEADDR`，便于重启，但不能绕过正在监听的端口占用。
