# Linux-IM-Server

Linux C++ 即时通信服务器学习项目。先完成 TCP 通信与 epoll Reactor，再逐步加入线程池、MySQL、Redis 和 HTTP/WebSocket。

## 当前进度

当前处于第 1 周第 3 天：单客户端阻塞式 TCP 通信。

- CMake 生成 `IMServer`、`IMClient` 两个可执行程序。
- 使用 C++17，关闭编译器语言扩展，开启 `-Wall -Wextra -Wpedantic`。
- 服务端校验参数数量及端口范围；客户端额外校验 IPv4 地址。
- 使用 RAII `Socket` 管理文件描述符，禁止拷贝，析构时关闭有效 fd。
- 服务端完成 `socket → bind → listen → accept`，打印客户端 IPv4 地址和端口，并循环接收数据。
- 客户端完成 `socket → connect`，循环读取终端输入并发送，支持空行和带空格文本。
- 发送循环处理部分发送，收发处理 `EINTR`；使用 `MSG_NOSIGNAL` 防止发送时被 `SIGPIPE` 终止。
- 客户端正常结束、服务端读到 EOF 时返回 `0`；参数错误或不可恢复的系统调用错误返回 `1`。

当前只处理一个客户端。该客户端断开后，服务端退出，不会继续接收下一个连接。尚未实现多客户端、消息转发、自定义帧协议或用户系统。

## 环境要求

- Linux
- 支持 C++17 的编译器（如 GCC）
- CMake 3.16 或更高版本
- Make 或其他 CMake 支持的构建工具
- Git；后续调试使用 GDB

当前阶段不依赖 MySQL、Redis、OpenSSL 或 Boost，后续按模块引入。

## 构建

以下命令均在项目根目录执行。

Debug 版本，用于开发和 GDB 调试：

```bash
cmake -S . -B build/debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build/debug -j
```

Release 版本，用于后续性能测试：

```bash
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release
cmake --build build/release -j
```

## 运行

在终端一启动服务端：

```bash
./build/debug/IMServer 8888
```

服务端绑定所有本机 IPv4 接口，并阻塞等待连接。在终端二启动客户端：

```bash
./build/debug/IMClient 127.0.0.1 8888
```

服务端接受一个端口参数；客户端接受一个 IPv4 地址和一个端口参数。端口必须是完整的十进制数字字符串，取值范围为 `1–65535`。客户端暂不接受域名或 IPv6 地址。

运行 Release 版本时，将路径中的 `debug` 替换为 `release`。

### 输入与退出

在客户端逐行输入文本，例如 `hello`、`hello world`。客户端会在每行末尾追加换行符，并发送完整数据；服务端按实际接收到的字节数直接输出内容。

- 输入 `/quit`：客户端正常退出，该命令不会发送给服务端。
- 在空输入行按 Ctrl+D：标准输入结束，客户端正常退出。
- 服务端收到连接 EOF：打印 `Client disconnected` 并正常退出。
- 服务端不发送回复，客户端也不接收服务端消息；本阶段只验证客户端到服务端的数据传输。

TCP 不保留应用消息边界，一次 `send()` 不一定对应一次 `recv()`。当前按字节流显示内容，不将一次接收视为一条完整消息。

## 手动验收

Debug 和 Release 两种构建都应无警告通过编译，并分别检查以下场景。

### 参数与连接

| 场景 | 预期行为 |
| --- | --- |
| 先启动服务端，再连接 `127.0.0.1:8888` | 连接成功，服务端打印正确的客户端 IP 和临时端口 |
| 缺少参数或多余参数 | 打印用法，返回 1 |
| 端口 `0`、`65536`、`-1`、`8888abc`、空字符串、超大整数 | 拒绝，返回 1 |
| 客户端地址 `999.1.1.1`、`abc`、空字符串 | 拒绝，返回 1 |
| 两个服务端绑定同一端口 | 第二个绑定失败，返回 1 |
| 本机目标端口没有监听服务 | 客户端连接失败，返回 1 |

端口 `1`、`65535` 均能通过参数校验，但后续绑定或连接能否成功取决于权限、端口占用和目标服务状态，不能仅据合法参数断言程序最终返回 0。

例如，执行错误参数测试后立即查看退出码：

```bash
./build/debug/IMServer 8888abc
echo $?
```

### 收发与断开

| 场景 | 预期行为 |
| --- | --- |
| 连续输入多行、带空格文本及空行 | 服务端完整显示字节内容，连接保持 |
| 发送超过 4096 字节的一行，例如 20000 字节 | 服务端分批接收，内容完整，无截断 |
| 输入 `/quit`，或标准输入到达 EOF | 客户端退出，服务端检测到 EOF，两端返回 0 |
| 强制结束客户端进程 | 服务端检测到 EOF 或接收错误，退出循环 |
| 对端重置连接后继续发送 | 客户端检测到发送错误后返回 1，不被 SIGPIPE 终止 |

对端关闭后，第一次发送可能仍然成功；本程序在下一次发送报告错误时才会发现，不能保证客户端在等待终端输入期间立即感知断开。

也可以在服务端启动后，通过管道验证连续发送与标准输入 EOF：

```bash
printf 'hello\nhello world\n\n' | ./build/debug/IMClient 127.0.0.1 8888
```

每轮测试结束后重新启动服务端。当前版本尚未设置 `SO_REUSEADDR`；如果重启绑定失败，应检查端口占用和 TCP 状态，或更换测试端口。

## 开发路线

| 周次 | 学习与实现内容 |
| --- | --- |
| 1 | 工程构建、参数校验、RAII Socket、基础 TCP 收发 |
| 2–3 | 非阻塞 epoll、Reactor 重构、连接生命周期与超时 |
| 4 | 自定义帧协议、拆包粘包、心跳、终端客户端 |
| 5 | pthread 线程池、有界任务队列、eventfd |
| 6–7 | MySQL 连接池、用户认证、群聊私聊、消息持久化 |
| 8–9 | Redis 会话与缓存、异步日志、优雅退出 |
| 10 | TCP 版回归测试、故障排查与压力测试 |
| 11–12 | HTTP/WebSocket 网关、浏览器测试客户端与最终交付 |

每阶段完成编码、测试、原理复述和 Git 提交后再推进。规划中的功能不代表已实现。

```text
IMServer/
├── CMakeLists.txt
├── README.md
├── include/
```
